## 契約與原有行為

H01 經 `server/adapters/ragic.ts` 讀取 `/xinsheng/ragicforms4/20004` 的 v3 分頁資料。parser 使用回傳的欄位名稱「員工編號」（欄位 id `3000935`）、「應徵職務」（`1002337`）；欄位 id 依本工單提供的唯讀調查，這次未呼叫真實 API。

員工以「員工編號」第一個非空值、去頭尾空白後對應 `employees.employeeCode`，不按姓名或 Ragic record id 對應。H01 同編號多筆時採最後解析成功的記錄。

應徵職務的多選陣列會逐項清洗空白、去掉空值，再以 `, ` 合併。`mapRole` 用 `includes` 依以下固定優先序取單一角色，與多選順序無關：救生、守望、櫃台（含櫃檯／櫃臺）、教練、機電、清潔、行政專員、資訊工程師、主管職、在校實習。未映射為「無職」。

H01 原同步僅對「救生／守望／櫃台／教練」的在職員工完整新增／更新；其他職務對既有員工走 inactive 判定，不完整更新 role。既有 status observation、管理員狀態調整與 missing 停用規則保留。

## 本次範圍

H02 使用 `/xinsheng/ragicforms4/13`，共用既有傳輸、分頁與多選映射。按 employeeCode 補既有員工的 role：H01 非空職務優先，H01 缺人或職務空白才用 H02。H01 先取原流程最後解析成功的職務；沒有可解析紀錄時，再讀 raw 職務，避免僅有姓名空白的 H01 紀錄被 H02 覆蓋。

H02 僅提供角色，不新增 H02-only 員工，不取代姓名、部門、聯絡資訊、狀態或 H01 快照完整性判定；無映射的職務保留既有 role。H02 例外單獨記一筆不含個資的同步錯誤，H01 交易繼續；`ragic.sync` 摘要 errors 交由既有 `ragic.employee-sync` 規則判黃。H01 失敗仍依原規則中止。

不改登入、權限矩陣、共用密碼開關與 health-hub，不呼叫真實 Ragic／LINE、不讀 `.env`、不碰開發庫／正式庫、不 push／Publish。沒有新資料表或 SQL。
